# ECHO (에코)

### 시간을 넘어 다시 울리는 목소리

**Hyundai Pleos Connect 기반 차량용 음성 타임캡슐 서비스**

---

## 프로젝트 소개

ECHO는 자동차 안에서 남긴 목소리를 미래의 특정 날짜에 다시 들을 수 있도록 설계한 차량용 음성 타임캡슐 서비스다. 사용자는 복잡한 입력 과정 대신 음성 안내와 간단한 터치 조작을 통해 기억을 녹음하고, 원하는 공개 날짜를 지정해 보관할 수 있다.

사진과 글로 남기는 기록과 달리 목소리에는 말투, 웃음, 당시의 감정과 주변 분위기가 함께 담긴다. ECHO는 이러한 음성의 고유한 가치를 보존하고, 시간이 흐른 뒤 다시 마주하는 경험을 제공하고자 한다.

차량은 일상적인 이동 공간이자 혼자 생각을 정리하거나 가족과 대화를 나누는 사적인 공간이다. ECHO는 그 공간에서 자연스럽게 생성되는 순간들을 미래의 기억으로 연결한다.

## 이름에 담긴 의미 — ECO에서 ECHO로

**ECHO**는 그리스어 *ēkhō*(메아리·울림)에서 유래한 영어 단어 *echo*를 바탕으로 한다. 한 번 울린 소리가 공간을 지나 다시 돌아오듯, 과거에 남긴 목소리가 미래의 어느 날 다시 들려온다는 서비스의 핵심 경험을 상징한다.

**ECO**는 일반적으로 *ecology*(생태학)나 *ecological*(생태적인)의 축약 표현으로 쓰이며, 그 어원은 그리스어 *oikos*(집·생활의 터전)와 연결된다. ECO와 ECHO가 같은 어원인 것은 아니지만, ECHO는 이 두 단어의 이미지를 창의적으로 결합한다.

- **ECO — 기억이 머무는 공간:** 자동차라는 일상의 작은 생활 공간에서 추억이 쌓이는 모습
- **ECHO — 시간을 건너 돌아오는 울림:** 그 공간에 남긴 목소리가 미래에 다시 들려오는 경험

즉, **“일상의 공간에 남긴 목소리가 시간을 지나 다시 울린다”**는 의미를 담았다. 여기서 ECO는 친환경 성능을 뜻하는 제품 주장이라기보다, 삶의 공간과 기억의 축적을 표현하는 브랜드 스토리다.

## 기획 배경과 서비스 가치

대부분의 디지털 기록은 촬영하거나 입력한 직후 확인하고 공유하는 방식에 집중되어 있다. 반면 ECHO는 **기록을 남기는 순간보다 다시 만나는 순간**에 주목한다.

오늘의 나에게는 평범한 한마디가 몇 년 뒤에는 특별한 기억이 될 수 있다. 처음 운전하던 날의 다짐, 가족과 떠난 여행의 웃음소리, 자녀에게 남기는 응원, 미래의 자신에게 보내는 메시지 등이 ECHO의 타임캡슐이 된다.

서비스는 다음의 가치를 중심으로 구성된다.

- **목소리 원본의 보존:** 텍스트로는 전달하기 어려운 억양과 감정까지 기록
- **미래의 재발견:** 지정한 날짜 전까지 봉인하고, 공개일 이후에 다시 감상
- **차량 환경에 맞춘 사용성:** 음성 안내와 큰 조작 요소로 화면 의존도를 최소화
- **오프라인 우선 설계:** 네트워크 연결 없이도 기본 녹음·저장·재생 흐름을 이용할 수 있도록 계획
- **장기적인 확장성:** 향후 가족 간 전달, 차량 변경 시 기록 승계, 개인 음성 아카이브로 확장

## 주요 이용 시나리오

### 미래의 나에게 메시지 남기기

사용자는 ECHO의 음성 호출 기능 또는 화면의 마이크 버튼을 통해 타임캡슐 생성을 시작한다.

> 사용자: “에코야, 3년 뒤에 들을 타임캡슐 만들어줘.”
>
> ECHO: “3년 뒤에 열리는 타임캡슐을 만들게요. 녹음을 시작할까요?”
>
> 사용자: “시작해줘.”
>
> ECHO: “녹음을 시작합니다.”

사용자는 미래의 자신에게 전하고 싶은 말을 자유롭게 남긴다. 녹음 종료 후에는 저장 여부를 확인하며, 사용자가 승인한 기록만 최종 타임캡슐로 봉인된다.

> ECHO: “녹음이 끝났어요. 3년 뒤에 열리는 타임캡슐로 저장할까요?”
>
> 사용자: “저장해줘.”
>
> ECHO: “타임캡슐을 저장했어요. 3년 뒤에 다시 만나요.”

공개일 이전에는 녹음 원본을 앱에서 재생할 수 없으며, 날짜가 도래하면 공개된 타임캡슐 목록에서 원본 음성을 다시 들을 수 있다.

### 공개된 기억 다시 듣기

> 사용자: “에코야, 열린 타임캡슐 들려줘.”
>
> ECHO: “3년 전 남긴 타임캡슐이 있어요. 들려드릴까요?”
>
> 사용자: “응, 들려줘.”

ECHO는 녹음 당시의 실제 목소리를 재생한다. 서비스가 안내하는 합성 음성과 사용자의 녹음 원본은 명확히 구분된다.

**안전한 사용을 위한 설계:** 위 대화는 목표 경험을 설명하는 예시다. 상시 호출어 감지 및 녹음 중 음성 명령의 지원 여부는 Pleos의 마이크·오디오 정책에 따라 검증한다. 지원되지 않는 환경에서는 화면 버튼과 재생 중심의 대체 흐름을 제공한다. 운전 중 긴 대화 내용을 화면에 표시하는 방식은 지양하며, 음성 안내와 ‘다시 듣기’를 우선한다.

## 핵심 서비스 구성

### 음성 중심의 타임캡슐 생성

ECHO는 호출어 인식, 음성 인식(STT), 명령 해석, 음성 합성(TTS)을 각각 독립된 구성요소로 설계한다. 초기에는 ‘생성’, ‘날짜 설정’, ‘녹음 시작·중지’, ‘저장’, ‘재생’ 등 명확한 명령을 규칙 기반으로 처리할 계획이다.

“에코야” 호출어는 서비스의 대표적인 사용 경험으로 제안하되, 상시 마이크 접근 가능 여부와 Pleos 정책 검증을 거쳐 적용 범위를 결정한다. 음성 인식이 어려운 경우에도 핵심 기능은 터치 UI로 이용할 수 있도록 한다.

### 공개 날짜 설정

공개 시점은 상대 기간 또는 특정 날짜로 지정할 수 있다. 예를 들어 ‘1개월 뒤’, ‘3년 뒤’, ‘10년 뒤’와 같은 기간 선택과 ‘2030년 12월 25일’, ‘내년 크리스마스’ 같은 날짜 입력을 지원하는 방향이다.

날짜 계산에는 Kotlin과 Java의 `java.time`을 활용하고, 월말·윤년·시간대 변경 등 경계 조건을 고려한다. 사용자가 확인한 공개일을 기준으로 봉인하며, 로컬 시간대와 저장 시간 기준은 일관된 정책으로 관리한다.

### 원본 음성 녹음 및 보존

녹음은 시작, 일시정지, 재개, 종료, 취소, 미리 듣기 과정을 포함한다. 음성 원본은 앱 전용 저장소에 보관하고, 메타데이터는 로컬 데이터베이스에서 관리한다. STT로 생성된 텍스트는 선택적인 보조 정보이며 원본 음성을 대체하지 않는다.

녹음 중 STT와 녹음 기능이 마이크를 동시에 사용할 수 있는지는 차량 환경에서 별도 검증한다. 저장 과정에서 오류가 발생했을 때 임시 파일 복구와 데이터 정합성을 유지하는 방안도 설계에 포함한다.

### 봉인과 공개

타임캡슐은 작성 중(`DRAFT`), 봉인(`SEALED`), 공개(`UNLOCKED`), 삭제(`DELETED`)의 상태로 관리한다. 봉인 중에는 제목과 공개 예정일 등 제한된 정보만 노출하고, 공개일 이전에는 앱의 일반적인 재생 경로를 차단한다.

초기 버전은 기기의 로컬 시계를 기준으로 공개 여부를 판단하므로, 기기 시간 변경에 대한 완전한 위·변조 방지까지 보장하지 않는다. 서버 기반 시각 검증과 다중 기기 동기화는 향후 확장 단계에서 검토한다.

### 공개된 타임캡슐 감상

공개된 기록은 목록에서 선택해 재생·일시정지·재개·종료할 수 있다. 재생 진행 시간과 상태를 명확하게 표시하고, 음성 안내를 통해 화면 확인 부담을 줄이는 방향으로 구성한다.

## 차량용 UI/UX 디자인

ECHO의 인터페이스는 현대자동차 Pleos Connect의 차량용 디자인 방향과 안전 정책을 우선으로 하며, 어두운 배경과 선명한 포인트 색상으로 차분하고 미래지향적인 분위기를 표현한다.

| 디자인 요소 | 제안 방향 |
|---|---|
| 기본 배경 | 딥 네이비 `#101A23` |
| 카드 배경 | 블루 그레이 `#1B2A35` |
| 강조 색상 | 민트 `#72DED1` |
| 텍스트 | 흰색 및 밝은 회색, 높은 명도 대비 |
| 조작 방식 | 음성 우선, 큰 버튼, 최소한의 메뉴 단계 |

### 홈 화면

중앙의 마이크와 음성 인식 상태를 중심으로 ‘타임캡슐 만들기’, ‘내 타임캡슐’에 빠르게 접근한다. 사용자가 처음 접하는 순간에도 서비스 목적과 시작 방법을 이해할 수 있도록 간결하게 구성한다.

### 공개 날짜 설정 화면

‘언제 다시 듣고 싶으세요?’라는 질문을 중심으로 기간 선택과 직접 날짜 선택을 제공한다. 1년·3년·5년·10년 빠른 선택과 공개 예정일 미리보기를 통해 조작 단계를 줄인다.

### 녹음 화면

녹음 시간, 진행 상태, 간단한 파형 표현, 일시정지와 종료 버튼에 집중한다. 시각적 효과는 상태를 전달하는 수준으로 제한해 불필요한 주의 분산을 방지한다.

### 내 타임캡슐 화면

‘봉인 중’과 ‘공개됨’으로 구분해 목록을 제공한다. 봉인된 기록은 자물쇠와 공개 예정일을, 공개된 기록은 재생 버튼과 공개일을 중심으로 표시한다.

실제 화면 구성과 터치 요소의 크기, 운전 중 허용되는 상호작용은 Pleos 공식 UI 가이드와 플랫폼 제약을 확인해 조정할 계획이다.

## 기술 구성 및 개발 방향

ECHO는 **Kotlin 기반 Android Automotive 애플리케이션**을 기본 방향으로 한다. Android Studio와 Gradle Kotlin DSL을 사용하고, 화면은 Jetpack Compose 적용 가능성을 우선 검토한다. Pleos Connect SDK와 공식 개발 환경에서 지원되는 API 수준, 라이브러리 및 UI 정책에 맞춰 최종 구성을 확정한다.

| 영역 | 적용 예정 기술·방식 |
|---|---|
| 플랫폼 | Hyundai Pleos Connect / Android Automotive 기반 |
| 언어 | Kotlin |
| UI | Jetpack Compose 우선 검토 |
| 아키텍처 | MVVM + Repository |
| 비동기·상태 관리 | Kotlin Coroutines + StateFlow |
| 로컬 데이터 | Room |
| 녹음·재생 | Android 오디오 API, Pleos 환경 호환성 확인 |
| 음성 인식 | 공식 지원 범위 검증 후 STT 연동 |
| 음성 안내 | Pleos TTS SDK 검증, 테스트 환경의 Android TTS 대체 검토 |
| 빌드 | Gradle Kotlin DSL |

기능별 패키지 분리를 통해 음성 인식, 명령 해석, 녹음, 재생, 저장 기능의 결합도를 낮춘다. 초기에는 단일 앱 모듈을 중심으로 구성해 과도한 멀티모듈화에 따른 복잡성을 피한다.

Flutter는 향후 연계 가능성을 열어 두되, 차량용 SDK 및 플랫폼 호환성을 우선하기 위해 초기 개발의 필수 기술로 채택하지 않는다.

### 음성 처리 구조

```text
호출어 감지 또는 마이크 버튼
           ↓
       음성 인식(STT)
           ↓
       명령·날짜 해석
           ↓
      사용자 의도 처리
           ↓
   녹음 / 저장 / 목록 / 재생
           ↓
       음성 안내(TTS)
```

호출어 감지(`WakeWordEngine`), STT(`SpeechRecognitionEngine`), 명령 분석(`VoiceCommandParser`), 명령 처리(`VoiceCommandProcessor`), TTS(`SpeechSynthesisEngine`), 녹음·재생(`AudioRecorder`, `AudioPlayer`) 및 저장소(`TimeCapsuleRepository`)는 교체 가능한 인터페이스로 설계한다.

초기 MVP는 외부 LLM이나 유료 AI 서비스에 의존하지 않는 것을 목표로 한다. 자연어 명령의 지원 범위는 오프라인 환경과 실제 음성 인식 엔진의 기능을 고려해 단계적으로 확대한다.

### 데이터 구조와 보존 정책

타임캡슐의 기본 데이터는 UUID, 제목, 생성 시각, 공개 시각, 상태, 음성 파일 경로, 녹음 길이로 구성한다. 향후 기능을 위해 소유자·수신자 식별자와 선택적 음성 인식 텍스트를 확장 필드로 고려한다.

Room 데이터베이스와 실제 오디오 파일의 불일치가 발생하지 않도록 임시 파일 처리, 저장 완료 확인, 오류 복구, 삭제 시 파일 정리 정책을 마련한다. 음성 데이터는 민감한 개인 기록으로 취급하며, 앱 전용 저장소와 접근 통제를 기본으로 하고 암호화 저장 및 백업 정책을 검토한다.

| UI 구축 | 홈, 공개 날짜, 녹음, 타임캡슐 목록 | 차량 화면에서 주요 흐름 확인 |
| 데이터 구현 | Room, 날짜 계산, 상태 전이, 파일 저장 | 봉인·공개 및 데이터 유지 |
| 오디오 구현 | 녹음, 일시정지, 재개, 재생, 복구 | 원본 음성의 안정적 저장·재생 |
| 음성 인터페이스 | STT, 명령 해석, TTS, 호출어 가능성 검증 | 음성 중심 사용 흐름 확인 |
| 통합 검증 | 오프라인 사용, 앱 재시작, 공개일 전후 동작, 에뮬레이터 테스트 | 주요 시나리오의 동작 검증 |

단계별 결과를 바탕으로 지원이 확인된 기능부터 완성도를 높이는 방식이다. 특히 호출어 감지, 동시 마이크 사용, 차량용 음성 API, 주행 중 UI 정책은 초기 기술 검증의 핵심 항목이다.

## 서비스 확장 가능성

### 1차 확장 — 기록을 더 쉽게 찾고 기억하기

자동 제목 생성, 녹음 내용 검색, 공개일 알림, 음성 내용 요약 등을 검토한다. 단, 음성 인식·요약 기능은 원본 녹음의 보존과 분리해 선택적으로 제공한다.

### 2차 확장 — 가족에게 전달하는 타임캡슐

가족 계정과 초대, 수신자 지정, 타임캡슐 공유, 서버 백업 및 여러 기기 간 동기화로 발전시킬 수 있다. 미래의 특정 날짜에 가족에게 목소리를 전달하는 기능은 개인 기록을 관계의 경험으로 확장하는 방향이다.

### 장기 확장 — 이동과 삶을 잇는 음성 아카이브

위치 기반 추억 재생, 과거 방문 장소와 기록의 연결, 차량 교체 시 데이터 승계, 가족 공동 타임라인을 구상하고 있다. 장기적으로 자동차에서 시작한 음성 기록을 세대를 이어 보존하는 개인·가족 아카이브로 확장하는 것이 목표다.

## 구현 가능성과 주요 검증 과제

ECHO의 기본 가치인 날짜 지정, 로컬 녹음, 파일 저장, 봉인 상태 관리, 공개 후 재생은 일반적인 Android 애플리케이션 기술을 바탕으로 설계할 수 있다. 다만 **Pleos Connect에서의 실제 배포 가능 여부와 API 지원 범위는 별도 검증이 필요하다.**

주요 검증 과제는 상시 호출어 감지 허용 여부, 녹음과 STT의 동시 마이크 사용 가능성, Pleos TTS 연동 방식, 오프라인 음성 인식 지원 여부, 차량 운행 상태별 UI 제한, 앱 데이터의 장기 보존 정책이다.

검증되지 않은 기능을 이미 제공되는 기능으로 전제하지 않고, 미지원 항목에는 터치 기반 대체 동선을 준비한다. 초기 버전은 사용자의 기기 시간에 의존하는 봉인 방식이며, 장기 보관을 위한 서버 백업과 신뢰 가능한 공개 시각 검증은 후속 개발 범위로 구분한다.

## 기대 효과와 지향점

ECHO는 차량 안에서 지나가는 순간을 미래의 소중한 기억으로 바꾸는 서비스다. 기존의 기록 도구가 ‘지금 남기고 지금 보는 경험’에 집중한다면, ECHO는 **‘지금 남기고 미래에 다시 듣는 경험’**에 의미를 둔다.

음성 중심 인터페이스는 차량 환경에 적합한 접근 방식을 제공하고, 실제 목소리의 보존은 텍스트나 사진과 구별되는 감성적 가치를 만든다. 향후 가족 간 타임캡슐 전달과 기록 승계가 가능해진다면, 개인의 추억을 가족의 시간으로 확장할 수 있다.

**오늘 남긴 목소리가, 미래의 어느 날 다시 나에게 돌아온다.**

이것이 ECHO가 만들고자 하는 경험이다.
